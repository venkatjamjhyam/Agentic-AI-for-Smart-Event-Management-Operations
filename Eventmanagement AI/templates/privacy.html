Privacy Policy

This page explains what information EventOps AI handles when you use the event management application and how to contact us with a privacy question.

Effective date: October 15, 2026

Operator details to complete: Replace “EventOps AI” with the legal name of the operator and provide a working privacy contact email before publishing this policy.

1. Information this application handles

Based on the current application code, EventOps AI handles information you enter or generate while using its features:

  • Account information: name, email address, and a password hash created when an account is registered. The application checks the hash during login; it does not store the password as plain text.
  • Event activity: event registrations, ticket type, check-in status, reminders, and feedback (rating and any comment), associated with your account where applicable.
  • Assistant messages: text you submit to the AI assistant may be sent to Google Gemini to generate a response. Do not include sensitive personal information in assistant prompts.
  • Contact form: the form asks for your name, email, subject, and message. In the current code, the submission is not saved or emailed; the app displays a confirmation and discards the submitted values after the request.

The application also creates timestamps for certain account, event, reminder, notification, and feedback records. Administrators may enter event and operations information into the system.

2. How information is used

The application uses account information to authenticate users and associate them with their registrations, reminders, and feedback. It uses event and operations records to provide dashboards and event management features. Assistant message text is sent to Gemini for response generation. The application code includes no payment processing feature.

3. Storage and retention

Application records are stored in the database configured by the operator. The default configuration uses a local SQLite database; a deployment may instead use the database specified by its environment configuration. The code does not define a data retention or account deletion schedule. The operator must set and publish those practices for the live service.

4. Cookies and similar technologies

The application uses Flask-Login for sign-in state, which relies on a browser session cookie. The application code does not define an analytics or advertising cookie system. The operator should confirm the production session-cookie settings and whether hosting infrastructure or added services use other cookies.

5. Service providers and external resources

Assistant prompts are sent to Google Gemini through the configured API integration. The shared page layout loads Bootstrap, Bootstrap Icons, and Chart.js from public content delivery networks; some pages also reference images hosted by Unsplash. Those providers may receive standard connection information from your browser when those resources load. Review the providers' terms and privacy information and confirm the exact services enabled in your deployment.

6. Security

Passwords are hashed by the application before they are stored. No website can guarantee absolute security; the operator should configure secure production hosting, protect database and API credentials, and enable appropriate transport security and session settings.

7. Your choices and questions

To ask about, correct, or request deletion of information associated with your account, contact the service operator using the privacy contact details published here. Add the operator's contact email, applicable response process, and any legal rights that apply where the service is offered before publication.

8. Changes to this policy

The operator may update this policy as the application or its data practices change. The effective date at the top of this page should be updated whenever the policy is revised.
